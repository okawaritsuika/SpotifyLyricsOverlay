# 아이마스 가사 오버레이 · Spotify

아이돌마스터 음악의 일본어 원문·후리가나·한국어 번역을 함께 보는 Windows 가사창입니다.
참여 아이돌·성우의 한국어 이름과 고유색을 표시하며, 기존 가사·싱크·곡별 보정과 설정을 유지합니다.

## Windows EXE 배포

[최신 Windows 배포 다운로드](https://github.com/okawaritsuika/SpotifyLyricsOverlay/releases/latest)에서
**Windows x64 ZIP**을 내려받아 모두 푼 뒤 `SpotifyLyricsOverlay.exe`를 실행하세요.
현재 화면에 필요한 `electron-runtime/` 폴더는 EXE 옆에 두세요.
이미 `electron-runtime/`이 있는 버전을 쓰고 있다면 앱 안에서 프로그램을 업데이트할 수 있습니다.
릴리스의 별도 EXE는 앱 내 프로그램 업데이트용 파일입니다.
Spotify 연결 모듈과 저장 가사·한국어 번역·싱크·음악 사전을 포함합니다.
AI 모델과 음원 분석 엔진은 필요한 경우에 설치합니다.
로그인 정보·개인 설정·브라우저 프로필·최근 기록은 배포에 넣지 않습니다.
포함 범위, 사용자 데이터 위치와 빌드 방법은 [DISTRIBUTION.md](DISTRIBUTION.md)를 참고하세요.

앱 시작 후 새 프로그램이나 사전·가사 자료를 자동으로 확인하고 새 항목이 있으면 알립니다.
**더 보기 → 프로그램·자료 업데이트**에서 새 자료를 받거나, 음악 사전의 **자료 갱신…**을 이용하세요.
자료는 새 곡과 비어 있는 항목에 추가하고 기존 시각·보정·직접 수정한 가사와 번역을 보존합니다.
원문이나 시각이 충돌하는 자료는 자동으로 적용하지 않습니다.

애플리케이션 코드는 [GNU GPL v3 또는 이후 버전](LICENSE)으로 배포합니다.
외부 라이브러리와 가사·번역·음악 자료에는 각 원저작자의 권리와 별도 고지가 적용됩니다.

Spotify에 시각이 있는 구절이 저장된 원문의 표기 차이 때문에 빠지면, 충분히 대응하는 현재 녹음의 원문으로 표시를 복구합니다.
확인된 번역과 직접 보정은 유지하며, 대응하지 않는 수동 보정이 있으면 자동 재구성을 보류합니다.
자동 조회용 브라우저는 작업 표시줄과 키보드 초점을 가져오지 않고 시작하며, 직접 누른 Spotify 로그인창은 정상적으로 열립니다.

## 화면에서 바로 사용하기

- **재생 / 일시정지**: 가사창 아래쪽 버튼으로 Spotify를 조작합니다. 헤더를 숨겨도 버튼이 남고, 실제 재생 상태에 맞춰 표시가 바뀝니다.
- **Spotify와 함께 시작 / 종료**: 더 보기 또는 우클릭 메뉴에서 설정합니다. 켜면 Windows 로그인 시 작은 감시기가 시작되어 Spotify를 실행할 때 가사창을 열고, Spotify 프로세스가 종료되면 설정을 저장한 뒤 가사 앱을 닫습니다. 최소화·일시정지·트레이에 숨기기는 종료로 취급하지 않습니다. 가사창만 직접 닫은 경우에는 Spotify를 다음에 실행할 때 다시 엽니다. 설정을 끄면 로그인 자동 실행도 해제됩니다.

숨김 번역 검색에 필요한 Spotify 원문이 늦게 도착하면 자동으로 다시 대조합니다. Spotify 로그인이 풀린 경우에도 다른 가사 제공자의 조회를 계속하므로 가사 화면을 열 때까지 기다리지 않습니다. 원문·번역 자료나 검증 가능한 싱크가 없는 곡까지 자동으로 확보되는 것은 아닙니다.

아이마스 음악 사전을 열면 현재 Spotify 곡을 찾아 표시합니다. 해당 녹음을 하나로 구분할 수 없으면 현재 곡의 검색 결과를 보여 줍니다.
탐색 후 검색창 옆 **현재 곡** 버튼으로 현재 Spotify 곡에 돌아갈 수 있습니다. 재생 중인 곡이나 저장한 연결은 바꾸지 않습니다.
사전의 **자동 연결**은 기존 Spotify 정보부터 연결하고, 현재 선택·보이는 목록·나머지 곡 순서로 녹음을 검색합니다.
제목·가창자·수록 앨범·길이가 맞는 단일 후보는 버튼 없이 연결합니다. 요청해 시작한 전체 연결 작업은 사전을 닫아도 앱에서 계속 진행하고, 앱을 재시작하면 저장한 위치부터 이어갑니다.
기존 수동 연결과 직접 해제한 항목은 자동으로 바꾸지 않습니다. 재생 버튼도 확정할 수 있는 후보는 자동 연결 후 실행합니다.
동명곡·다른 버전·복수 후보는 보류하며, 검색한 제목은 24시간 안에 자동으로 반복 조회하지 않습니다.
사전 상단은 제목 수와 녹음 수를 구분하며, 자동 연결 상태에는 검색 대상 제목 수·검색 시도·미검색·미확정 수를 표시합니다.
대사·연주를 포함한 전체 녹음을 대상으로 확인합니다. 플레이리스트는 마지막 페이지까지 읽은 항목 수와 Spotify의 총수를 대조합니다. 검색 이력은 Spotify 수록 여부를 모두 확인했다는 뜻이 아니며, 반복 오류 항목은 따로 기록하고 나머지를 계속 처리합니다.

요청해 시작한 **플레이리스트 가사 일괄 수집**은 곡을 재생하지 않고 Spotify 원문·싱크를 읽으며, 조회를 마친 곡부터 저장된 번역과 지원되는 공개 출처로 부족한 한국어 번역·싱크를 동시에 보완합니다. 두 작업은 각각 요청 제한 대기 시간을 지키고, 저장은 앱에서 순서대로 처리합니다. 진행 위치와 곡별 결과를 저장하므로 앱을 다시 실행하면 이어갑니다. 기존 직접 입력과 수동 시각은 바꾸지 않습니다.
목록의 순서·중복·미확보 항목을 보존하고, 결과는 최근 200곡 캐시와 별개로 `data/playlist_lyrics/`에 계속 보관합니다. 같은 음원의 곡명·가수·앨범·길이가 확인되면 재생할 때 이 자료를 불러옵니다. 번역을 다른 버전에 재사용할 때는 전체 원문을 대조하고, 다른 녹음의 싱크는 옮기지 않습니다.
시각이나 번역이 비어 있는 곡을 완료로 표시하지 않습니다. `tools/audit_playlist_lyrics.py --save`로 저장 파일 전체와 누락 수를 확인할 수 있습니다. 요청한 작업 후 PC 종료는 별도 후속 확인 작업이 완료 조건을 검증한 뒤 실행하며, 가사 수집 코드 자체가 PC를 끄지는 않습니다.

직접 대조를 마친 번역은 `data/playlist_lyrics/reviewed/{Spotify ID}.json`으로 전달할 수 있습니다. 형식은 `schema_version: 1`, `track`의 `id/title/album/duration`, `lines`의 `original/reading/korean`입니다. 원자적으로 저장한 파일만 사용하고, 원문 배열은 기존 저장 자료와 문자·순서까지 같아야 합니다. 앱이 5초마다 한 파일을 확인해 빈 번역과 읽기만 채우며, 전달된 시각은 사용하지 않습니다. 적용 결과와 SHA256은 `playlist_lyrics_job.json`의 `reviewed_imports`에 남습니다. 기존 가사 저장소를 실행 중에 직접 수정할 필요가 없습니다.

- **가사 연결**: **더 보기 → 개발자 모드 → 가사 연결**에서 Spotify와 선택 가사 제공자의 연결 상태를 확인합니다.
- **Electron 개발자 모드**에서 회색 테두리는 선택한 줄, 분홍색은 가사창에 표시 중인 줄입니다. **선택 줄 가운데**를 켜면 편집할 줄이 목록 가운데에 옵니다. 가사 본문이나 줄 옆 **이동**을 클릭하거나 **← / →**를 누르면 줄을 선택하고 해당 싱크로 재생을 옮깁니다. **Enter**나 **현재 싱크로**를 누르면 분홍 줄이 선택됩니다. 현재 재생 시각을 저장하려면 **선택 줄 기록**을 누르세요. **심플 창**에서도 싱크 기록과 가창자 지정 단축키, 가창자 번호, **다음 작업곡**을 쓸 수 있습니다. **편집**으로 원문·읽기·번역을 열고 심플 창에서는 **저장**, 전체 모드에서는 **가사 수정 적용**을 누르세요.
- **음원 분석 → 재생목록 분석**에서 Spotify 공유 링크를 불러오거나 기본 재생목록을 선택합니다. 전용 Virtual Desktop Audio 출력으로 한 곡을 끝까지 무음 수집한 뒤 그 곡의 싱크를 분석합니다. 분석을 마치면 다음 곡으로 넘어갑니다. **분석 중지**는 Spotify를 일시정지하고 원래 출력을 복원합니다.
- **개발자 모드 · 수동 싱크**: 더 보기/우클릭 메뉴에서 현재 곡의 가사와 싱크를 편집합니다. Spotify 싱크가 없는 곡에는 녹음과 가사가 일치하는 AI 시각을 먼저 표시합니다. 가사창은 저장된 싱크와 Spotify 재생 시각을 따르고, 개발자 표는 선택 줄을 가운데에 둡니다. **재생 줄 표시**를 켜면 기본 개발자 표의 시각에 따른 재생 줄에 ▶가 표시됩니다. **← / →**로 앞뒤 줄을 선택하면 해당 줄의 시작 시각으로 Spotify가 이동합니다. **Q / W / E / R**은 각각 −5 / −2 / +1 / +5초 이동합니다. **↓**는 다음 줄의 시작을 즉시 저장하고 그 줄을 선택합니다. 가사 오버레이에서 **Enter**를 누르거나 개발자 모드에서 **선택 줄 기록**을 누르면 선택 줄의 시작을 저장합니다. **선택 줄 듣기**는 해당 시각 2초 전으로 이동합니다. **다음 작업곡**으로 이어갑니다.
  **곡 참여 가창자 편집**에서 브랜드를 고르고 가창자를 추가하거나 삭제한 뒤 저장합니다. 명단 순서대로 **1–9, 0** 키가 배정되며, 가창자 버튼과 가사 줄의 이름 옆에 배정된 번호가 표시됩니다. 개발자 표에서 줄을 선택하고 해당 숫자 키를 눌러 가창자를 지정합니다. 여러 키를 눌러 합창을 지정하거나 같은 키를 다시 눌러 해당 가창자를 뺄 수 있습니다. 개발자 모드의 **가창자 입력** 버튼으로 입력을 켜고 **Esc**로 닫을 수 있습니다. 시작 시각이 비어 있는 줄은 **싱크 없음**으로 표시합니다.
  개발자 표의 **가사 칸을 더블 클릭**하면 그 자리에서 한 줄을 수정할 수 있습니다. **Enter**로 저장하면 가사창에 즉시 반영되고, **Esc**로 취소할 수 있습니다. 기존 싱크와 가창자 지정은 같은 줄에 유지됩니다.
  **선택 줄 싱크 지우기** 또는 **Delete**는 선택 줄의 시각을 즉시 지웁니다. 뒤 소절 시각이 겹치면 오류에 나온 줄을 먼저 지운 뒤 앞 소절을 저장하고, 뒤 소절도 이어서 기록합니다.
  가사창과 개발자 표에서 **↑**를 누르면 앞 소절의 끝과 현재 줄의 시작을 지금 재생 시각으로 저장합니다. 개발자 모드에서는 두 창 모두 표에서 선택한 줄이 기준입니다.
  **알송 가사 찾기**에서 현재 곡의 제목·가수·앨범을 확인하고 수정한 뒤 **검색**을 누릅니다. 제목과 가수는 알송에 전송되고, 앨범은 결과 정렬에 사용합니다. 등록본을 **미리보기**로 확인한 뒤 **현재 곡에 임시 연결**하면 가사창과 개발자 표에 표시됩니다. **알송 임시 연결 해제** 또는 곡 전환으로 연결이 끝납니다. 직접 기록한 시각은 같은 곡에서 같은 등록본을 다시 연결할 때 불러옵니다.
  미리보기에서 원문·독음·한국어 번역을 확인할 수 있습니다. 일본어 독음이 비어 있으면 로컬 사전으로 보충합니다. Spotify 곡 길이, 알송이 제공한 곡 길이, 마지막 가사 시작 시각은 각각 표시합니다.
  개발자 모드를 열면 현재 곡의 가사를 편집할 수 있습니다. **앞에 가사 추가**는 선택 줄 바로 앞에 새 가사를 넣고, **가사 줄 삭제**는 선택한 줄을 지웁니다. Spotify와 알송 등 가사 출처에 관계없이 쓸 수 있습니다. 새 줄의 시작 시각은 **Enter**로 기록합니다. **다음 작업곡**을 누르면 Spotify 싱크가 없는 곡을 찾습니다.
  선택한 알송 가사를 계속 사용하려면 개발자 표 아래 **알송 확정**을 누릅니다. 같은 곡을 재생하면 확정한 등록본과 수정 내역이 자동으로 열립니다. **알송 확정 해제**를 누르면 원래 가사 연결로 돌아갑니다.
기존 AI 번역 저장 자료는 `data/ai_translations/`에서 계속 읽으며, 원문·직접 수정·수동 싱크는 보존합니다.
- **가사 표시 설정**: 제목, 곡 가창자, 구절 가창자, 원문·읽는 법·번역과 좌우 이전·다음 구절의 글꼴과 표시를 각각 조절합니다. Noto Sans KR·JP, Noto Serif JP, 고운 돋움, 나눔명조를 함께 제공합니다. 미리보기에서 확인한 뒤 상단 **적용**을 누르면 실제 가사창에 반영됩니다. 프리셋은 이름을 붙여 저장할 수 있습니다.
- **좌우 미리 가사**: 공간이 넉넉하면 왼쪽에 이전 구절의 끝, 오른쪽에 다음 구절의 시작을 작게 표시합니다. 긴 줄은 말줄임표로 표시합니다.
- **음량**: 가사창 하단의 버튼으로 0~100% 슬라이더와 음소거를 엽니다. Spotify 자체 음량·음소거와 연동되어 어느 쪽에서 바꿔도 같은 값을 표시합니다. Spotify가 제공하는 조절 단위(현재 10%)를 따르며, 조절창이 열려 있는 동안 Spotify의 변경을 주기적으로 읽습니다. Windows 볼륨 믹서는 변경하지 않습니다. 연결되지 않으면 Spotify 데스크톱 창을 열어 주세요.

## 처음 연결하기

1. **Spotify 연결**: 열린 Spotify 창에서 한 번 로그인합니다. 연결을 기억하므로 다음 실행부터 자동으로 연결합니다.

나무위키가 없어도 Spotify 등에서 받은 원문과 알송 전체 가사의 대조를 통과하면, 같은 시각의 일본어·한글 독음·한글 번역 3줄 형식에서 빈 독음과 번역을 채워 저장합니다. 오탈자가 포함된 자료의 번역은 순서와 원문이 정확히 맞는 구절에만 보충하며, 반복 구절의 다른 번역을 가져오지 않습니다. 한글 한 줄만 있거나 순서를 구분할 수 없는 형식은 번역이라고 추측해 넣지 않습니다. 기존 원문·번역과 수동 보정, 우선순위가 높은 Spotify 시간표는 유지합니다. 알송에 없는 번역을 새로 생성하는 기능은 아닙니다.
알송의 여러 등록본은 대응하는 구절의 시간이 모든 후보 쌍에서 0.5초 이내로 차이 나면 사용할 수 있습니다. 문자 차이·시간표 완성도·번역 수·등록 ID 순서로 한 등록본을 선택하고 그 실제 시각을 저장합니다. 여러 시간표를 평균 내거나 없는 시각을 만들지 않으며, 이후 재생에는 저장한 결과를 재사용합니다.
알송의 협업 가수 표기 `A x B`, `A × B`, `A & B`도 구분합니다. 검색 0건, 곡명·가수 불일치, 가사는 있으나 자동 적용 조건 불일치, 한글 번역 부재를 연결 상태에서 구분합니다. 등록된 곡이 있다는 사실만으로 한국어 번역까지 있다는 뜻은 아닙니다.

LRCLIB는 첫 검색에서 사용할 싱크를 찾지 못하면 제목만으로 한 번 더 검색합니다. 가수의 말미 CV 괄호 생략은 허용하지만 서로 다른 성우·가수·버전·앨범·길이는 거절하고, 시각이 충돌하는 등록본은 보류합니다. 알송도 첫 검색에 제목·가수가 맞는 후보가 없으면 제목만으로 한 번 더 검색합니다. 상세 조회 한도 초과는 후보 미검증으로 표시합니다. 연결 화면에는 LRCLIB 결과와 LyricsPlus의 원문·시각 검증 실패를 따로 보여주며, 조회 오류나 제한된 검색의 미발견을 전체 출처의 싱크 부재로 단정하지 않습니다.

2026-10-03 `Walking on the Square`의 알송 싱크를 찾지 못하던 원인은 선두 앨범·곡명 소개와 영어 원문·발음·번역 슬롯의 동일 문장 3회 반복을 가사로 읽은 것이었습니다. 일본어 3행 형식이 확인되는 문서의 동일 시각 영어 슬롯과 선두 메타데이터만 정리하며, 정리한 전체 원문이 현재 가사와 정확히 같아야 인정합니다. 실제 등록본 11289476은 34줄 전체가 일치하고 7.97~254.41초 시각이 275.426초 음원 범위 안에 있음을 확인했습니다. 오프라인 앱 검증에서도 기존 번역과 수동 보정을 유지했습니다. 이는 제공자 문서 대조 결과이며 실제 가창 시각을 청취 검증한 결과는 아닙니다.

Spotify와 알송의 괄호 속 부가보컬 표기가 달라 싱크 대조를 통과하지 못한 경우에는 번역 보충을 따로 검사합니다. 알송에만 있는 괄호 구절을 제외한 본문 전체가 기존 대조 검사를 통과해야 하며, 원문과 순서·구절 범위가 정확히 같은 부분에만 번역을 붙입니다. 기존 원문·Spotify 시간표·수동 보정을 유지하고 받은 번역은 가사 캐시에 저장합니다. 줄 구분이 다른 번역을 임의로 쪼개거나 해당 등록본의 싱크까지 적용하지 않습니다.
프로토콜 참고: [ivLyrics 공급자](https://github.com/ivLis-Studio/ivLyrics/blob/main/Addon_Lyrics_LyricsPlus.js), [LyricsPlus API 규격](https://github.com/ibratabian17/LyricsPlus/blob/gelato/docs/endpoints.md), [사용자가 지정한 lyrs-eggsong 공급자](https://github.com/medAndro/lyrs-eggsong/blob/main/src/provider.js). 알송의 요청 규격과 공개 클라이언트 상수를 참고해 Python으로 구현했으며 계정 인증값을 추출하지 않습니다.

2026-10-01 `ときめきエモーション`의 [PetitLyrics 등록본 4153963](https://petitlyrics.com/lyrics/4153963)은 `文字同期`로 분류돼 있음을 확인했습니다.
그러나 신규 익명 브라우저에서 정상 공개 뷰어를 실행해 받은 응답은 가사 항목 76개로, 각 항목은 `lyrics` 필드만 갖고 시간·음원 길이 또는 LRC 시각 정보가 없었습니다.
싱크 등록 분류를 외부 앱에서 타임스탬프를 취득할 수 있다는 뜻으로 해석하면 안 됩니다. 현재 공개 웹 경로만으로는 이 싱크를 자동 연결할 수 없으며,
[공식 API·SDK](https://syncpower.jp/ja/news/2016/0510/1)의 접근 정보와 시간 데이터 규격을 확인하기 전에는 동작하지 않는 공급자 옵션을 추가하지 않습니다.

## 버전명 제목 검색과 연결 기억

`Crossing! (如月千早 Ver.)`처럼 가수명·버전명이 붙은 곡은 전체 제목을 먼저 찾고,
`Ver.`·`Version`·`Recording`·`Remastered`·`버전`·`バージョン`을 뺀 제목도 차례로 확인합니다.
전각 괄호·대괄호·중첩 괄호와 대시로 분리된 버전명에 같은 규칙을 적용합니다.
그 밖의 말미 괄호도 검색 후보로 시도합니다. 제목의 일부일 수 있으므로 Spotify 원문 대조,
문서 본문의 정식 제목·아티스트 일치 또는 직접 선택으로 확인합니다.
예를 들어 `アイ NEED YOU（FOR WONDERFUL STORY） - … Piano Arrange Version`은
전체 제목, `アイ NEED YOU(FOR WONDERFUL STORY)`, `アイ NEED YOU` 순서로 확인합니다.

가사창에 표시가 성공한 문서 주소는 제목·아티스트·앨범별로 기억해 다음 재생에 먼저 사용합니다.
자동으로 기억한 주소도 새 Spotify 원문과 다르면 다시 대조하고, 사용자가 직접 지정한 주소는 자동 결과로 덮지 않습니다.
검증된 가사는 곡별 캐시에 보관하며 같은 가사 문서를 사용해도 버전별 싱크는 별도입니다.
내부 브라우저 탐색 중 원문이 뒤늦게 들어오면 미확정 후보를 한 번 더 확인합니다.
앱을 재시작하면 적용되며, Chrome 확장 모드는 확장도 2.6.1로 새로고침해야 합니다.

내부 브라우저의 시간 초과는 초기화·원본 문서 로딩·가사 표 읽기·문서 후보 검색 중 발생 단계를 표시합니다.
시간 초과에만 5초·15초 간격으로 최대 두 번 자동 재시도하며, 곡이 바뀌거나 연결을 끄면 취소합니다.
일시 정지 중에는 기다립니다. 접근 제한·가사 없음·스크립트 오류에는 이 재시도를 적용하지 않습니다.
이미 로딩한 문서를 다시 확인할 때는 현재 페이지를 재사용합니다. 같은 주소의 재방문이나 주소의 인코딩·
리다이렉트 차이 때문에 발생하지 않는 새 로딩 완료 신호를 기다리지 않습니다.

## 번역 연결과 화면 읽기 보조 기능

나무위키의 `dear…` / `dear...`처럼 유니코드 표기가 같은 문서 주소와 리다이렉트의 `?from=`은
같은 연결로 처리합니다. 번역 없이 영어 원문만 있는 후렴은 원문·독음으로 유지하고 다음 구절의
번역을 당겨 붙이지 않습니다. 한글 발음만 있는 불완전한 묶음은 URL·붙여넣기 가져오기에서 계속 거부합니다.

Spotify 연결·공개 싱크를 사용하지 않는 기존 화면 보조 모드에서는
일반 가사 화면과 동기화된 전체화면 가사에서 현재 강조 구절을 읽습니다. 화면이 갱신되어 기존
강조 정보를 잃으면 다시 읽고, 처음에 동기화되지 않은 가사로 나타났다가 싱크가 생기는 경우에도
같은 곡에서 재확인합니다. 코드를 업데이트한 뒤에는 실행 중인 가사 앱을 재시작해야 적용됩니다.

Spotify와 번역의 줄바꿈이 다르면 이어지는 원문을 최대 6줄씩 대조해 같은 구절로 연결합니다.
번역에 대응하지 않는 추임새는 이전 구절에서 기다리고 다음 확인된 구절에서 따라가기를 이어갑니다.
이 때문에 후반부의 마지막 번역으로 앞서 넘어가 고정되지 않도록 했습니다. 분할·병합된 구절의
강조는 표시용으로 사용하며 정확한 일대일 구절 전환만 시각으로 기억합니다.

## AI 음원 분석은 선택 설치

일본어 노래의 음소 정렬 후보를 검토하려면 [RomajiASR와 pyshiro v2 설치·평가 안내](JAPANESE_ALIGNMENT.md)를 참고하세요.

같은 녹음의 로컬 파일이 있으면 **개발자 모드 → 음원 분석 → 로컬 음원 분석**을 사용할 수 있습니다. 파일 등록, 검토용 싱크, 캐릭터 음성 프로필과 일괄 처리 방법은 [로컬 음원 분석](LOCAL_AUDIO_ANALYSIS.md)에 있습니다.

기본 설치에는 내부 브라우저·가사 표시·후리가나·수동 싱크를 포함하고 **음원 분석 모델과 Torch는 포함하지 않습니다.**
AI가 없어도 번역 연결, Spotify 강조 추적, 기존에 저장한 시간표와 수동 보정은 사용할 수 있습니다.

음원 분석이 필요할 때 **개발자 모드 → 음원 분석 → AI 선택 설치… → AI 다운로드·설치**를 누릅니다. 창을 열거나 자동 분석 옵션을 누르는 것만으로는 다운로드하지 않습니다.
CPU용 Whisper small 모델은 약 486MB입니다. NVIDIA 환경의 선택 설치에는 실시간용 Whisper medium(약 1.53GB)과 GPU 런타임도 포함됩니다. CPU 기준 새 선택 설치는 검증한 Torch 빌드 파일 5개(약 2.67GB)를
설치 마지막에 정리하고 pip 다운로드 캐시·일괄 바이트코드 생성을 끕니다. 완료 후 전체 약 1.8GB를 예상하며 환경별 차이가 있습니다.
설치 중에는 정리 전 파일(기존 측정 약 4.5GB)과 다운로드 임시 공간이 추가로 필요합니다. 다운로드 양이 1.8GB라는 뜻은 아닙니다.
이미 설치된 사용자의 파일은 앱 시작만으로 정리하지 않습니다. 앱 폴더 내부의 검증한 CPU Torch만 명시적인 설치 작업에서 정리합니다.

설치 단계·로그와 취소 버튼을 제공하며, 실패·취소 후 다시 다운로드를 누를 수 있습니다.
설치창을 닫으면 백그라운드에서 계속하고 다시 열면 진행 상태를 볼 수 있습니다. 앱을 종료하면 해당 설치 작업도 취소합니다.
설치가 끝나도 자동 분석을 저절로 켜지 않습니다. 필요한 때 **자동 분석 · Spotify 소리만**을 켜거나 분석 대기를 시작합니다.
이미 준비된 모델은 중복 설치하지 않으며 기존에 설치된 모델·사용자의 가사·시간표를 삭제하지 않습니다.
수동 설치를 원하면 `setup-audio.ps1`도 계속 사용할 수 있습니다.

## 기존에 저장한 가사와 가져오기 형식

이전 버전에서 저장한 가사, 직접 입력한 원문·독음·번역, TXT 자료와 수동 싱크는 계속 읽습니다. 기존 가져오기 자료의 한 줄 원문, 원문/번역 두 줄 묶음, 원문/독음/번역 세 줄 묶음 형식도 그대로 유지합니다. 기존 수정 백업은 `data/lyric_edit_backups/`에 남습니다. 현재 곡의 가사 줄은 **개발자 모드**에서 편집할 수 있습니다.

## 저장된 TXT의 누락 구절 보충

Spotify 가사 화면에서 전체 원문을 읽었을 때, 저장된 모든 구절이 순서대로 일치하면 빠진 구절을
메모리에서 보충합니다. Spotify의 줄바꿈 차이는 기존 구절로 묶어 원래 번역·독음·수동 시각을 유지합니다.
부분 화면이나 다른 곡처럼 전체 순서가 일치하지 않는 결과는 적용하지 않습니다.
추가된 구절은 원문·독음부터 표시하고 번역이 수신되면 연결합니다. 새 구절에 정확한 시각이 없으면
추정 진행을 사용하므로 개발자 모드에서 추가로 교정해야 합니다. 기존 시각의 정확성 자체를 재검증하는 기능은 아닙니다.
보충본에서 기록한 시각은 본문 없이 별도 시간표로 보관하고, 다음에 같은 원문을 읽으면 복원합니다.
동기화되지 않은 정적 가사는 전체 가사 영역의 접근성 텍스트를 사용하며 강조 시각은 추측하지 않습니다.
기존 TXT·라이브러리·기존 시간표는 그대로 유지합니다. Spotify 가사 화면을 열어야 보충 원문을 받을 수 있습니다.

## 가사 웹 연결 방식 (2.6.0)

기본 연결은 **앱 내부 브라우저**이며 Chrome이나 확장을 실행할 필요가 없습니다.
**더 보기 → 개발자 모드 → 가사 연결**에서 연결 상태를 확인합니다.
기존 Chrome 연결은 호환용 선택지로 남아 있지만 내부 연결 실패 시 자동으로 전환하지 않습니다.

- **앱 내부 브라우저:** Chrome과 확장이 없어도 WebView2로 원본 문서를 확인합니다.
  평소에는 창을 표시하지 않고, 가사창 수신 완료 후 브라우저 프로세스를 종료합니다.
  자동 연결은 재생 중인 곡이 바뀔 때 한 번 시작하며 동명 후보는 최대 8개까지 대조합니다.
  후보가 구분되지 않으면 연결 설정에서 문서를 선택합니다. 접근 확인이 필요하면 자동 탐색을 멈추고
  `원본 확인`으로 사용자가 직접 원본 창을 열 수 있습니다. 사이트 확인 절차를 자동으로 처리하지 않습니다.
- **Chrome 확장:** 기존 확장 v2.6.0을 사용합니다. 수신 완료가 확인되면 확장이 만든 비활성 탭만 닫습니다.
  사용자가 열어 본 탭·고정 탭·다른 주소로 이동한 탭, 연결 실패·후보 선택 대기는 자동으로 닫지 않습니다.
  같은 곡에서는 닫힌 탭을 반복해서 다시 열지 않습니다.

내부 브라우저 선택 시 새 확장은 Chrome 자동 연결을 대기시켜 중복 수신을 막습니다.
이 방식에서는 확장을 꺼도 연결되며, 기존 확장을 계속 켜둘 때는 새로고침으로 v2.6.0을 적용하세요.
Chrome 방식으로 돌아가면 같은 곡도 다시 연결합니다.

Windows EXE에 내부 브라우저 모듈이 들어 있으며 Windows의 WebView2 Runtime을 사용합니다.
소스로 실행할 때는 `setup.ps1`이 모듈도 설치합니다. 소스 설치에 모듈만 추가할 때는 `setup-browser.ps1`을 실행합니다.
새 설치는 내부 방식을 기본으로 사용하고 사용자가 저장한 선택은 유지합니다.
내부 브라우저 프로필은 데이터 폴더의 `browser_profile/`입니다.
Chrome 프로필·쿠키는 복사하지 않습니다. 접속 정보와 웹 캐시는 WebView2가 이 프로필에서 관리하며,
가사 추출 결과는 메모리 파이프로 앱에 전달하고, 앱은 검증한 결과를 `data/lyrics_cache/`에 보관합니다.

로컬 합성 표 시험: 준비·읽기 약 1.1~3.4초, 전용 메모리 최고 약 175MiB,
공유 메모리를 중복 포함한 프로세스별 작업 집합 합계 최고 약 409MiB였습니다.
종료 2초 뒤 시험 프로세스가 모두 종료된 것을 확인했습니다. 실제 사이트의 접속 시간·메모리·성공률은 다를 수 있습니다.

Windows의 Spotify 데스크톱 앱을 감지하여 일본어 원문, 히라가나 독음, 한국어
번역을 작업 화면 아래에 표시합니다. 3줄 형식 TXT 또는 나무위키의 가사 표를
가져올 수 있습니다. 한국어는 문서에 실린 번역을 사용하고, 웹에서 가져온 일본어의
히라가나 독음은 로컬 사전으로 생성합니다. Spotify·번역 API 키와 유료 서비스는 필요 없습니다.

**더 보기 → 개발자 모드 → 가사 연결 → Spotify 연결**에서 앱 전용 창에 한 번 로그인하면,
Spotify 데스크톱을 최소화하거나 가사 화면을 닫아도 원문과 제공되는 줄별 싱크를 조회합니다.
로그인 뒤 연결 창은 숨겨지며, 재시작 때 `data/spotify_profile/`의 앱 전용 세션을 다시 사용합니다.
가사는 기존 Windows 재생 시계를 따릅니다. 이전 곡·다음 곡 버튼을 직접 누를 때만 Spotify에 곡 이동을 요청합니다.
Spotify 검색 결과의 전체 곡명·가수·길이와 앨범을 확인하므로 다른 버전의 시각을 섞지 않습니다.
Spotify에서 싱크를 제공하지 않는 곡은 정확한 싱크로 표시하지 않으며 기존 추정·수동 보정을 유지합니다.
검증된 직접 조회 가사와 제공자 시간표는 `data/lyrics_cache/`에 보관하며, 사용자가 보정한 숫자 시간표는 기존 저장소에 별도로 저장합니다.
번역의 줄바꿈이 달라져도 대응되는 수동 시각과 오프셋은 유지합니다.

가사 연결 화면의 **로그인 없이 시작**을 선택하면 곡명과 아티스트를 `lrclib.net`으로 보내
로그인 없이 공개 원문·싱크를 조회합니다. 앨범과 재생 길이는 받은 후보를 로컬에서 검증할 때만 사용합니다.
이 보조 조회는 기본으로 꺼져 있습니다. 자동 조회는 곡별로 한 번, 통신 실패 시 한 번 더 시도합니다.
Spotify의 내부 가사 API는 공개 Web API가 아니므로 서버 변경이나 계정 상태에 따라 연결을 다시 해야 할 수 있습니다.
연결 상태와 실패 사유는 가사 연결 화면에서 확인합니다.

직접 조회로 충분한 싱크를 받으면 화면 읽기를 중단합니다. 보조 경로로 Spotify의 가사 화면을 열면 접근성 텍스트에서 원문을 읽어 기존 가사창에 표시합니다.
원문을 읽을 수 없을 때에는 전면 Spotify 창의 일본어 OCR을 대조용으로 보완합니다.
원문과 후리가나는 먼저 표시하고 한국어는 확장으로 받은 번역을 연결합니다.
Spotify가 강조한 현재 구절의 색상 정보를 읽을 수 있으면 그 구절을 직접 따라갑니다.
진행 중에는 실제 강조의 이동량과 주변 구절을 대조해 순서를 우선합니다. 중간 강조를
놓쳤거나 추정 진행이 앞서갔어도 확인된 실제 구절로 다시 맞춥니다. 강조 정보를 잠깐 놓쳐도
마지막 확인 위치부터 이어가며, 사용자가 재생 위치를 옮기면 새 위치에 다시 맞춥니다.
직접 수정한 구절의 시각을 우선하고 나머지 구절은 자동 싱크를 계속 사용합니다. 검토하지 않은 음원 분석 결과는
Spotify의 실제 강조 구절을 가리지 않습니다. 실제 강조가 연속해서 다음 구절로 바뀐
순간은 숫자 시간만 `data/native_timings/`에 기억해 다음 재생과 최소화 때 재사용합니다.
중간부터 관측한 첫 구절, 건너뛴 구절, 탐색 직후와 오래 끊긴 관측은 기록하지 않습니다.
이 저장소에는 가사 본문·음원을 넣지 않으며, 기존 수동 시간표도 바꾸지 않습니다.
강조를 읽은 실제 시각으로 시간을 기억하며, 창 처리가 늦게 끝난 시각을 시작 시간으로
기록하지 않습니다. 같은 원문의 번역·독음만 갱신돼도 기억한 시간과 직접 선택한 구절을 유지합니다.
읽지 못하거나 강조가 모호하면 기존 추정 싱크로 돌아가며 화면에 모드를 표시합니다.
가사가 준비되면 전주·첫 음원 분석 대기 중에도 첫 소절을 먼저 보여주고, 시작 시각이나 실제 구절을 확인하면 그 위치를 따라갑니다.
`La...`·`ラララ`처럼 반복 음절만 적힌 구절은 글자 수나 앞 구절의 말 빠르기로
끝나는 시간을 정하지 않습니다. 다음 구절의 음원 일치·Spotify 강조·저장한 시각이
확인될 때 넘어가고, 근거가 없으면 `반복 구절 · 다음 구절 확인 대기`로 머뭅니다.
이 대기는 실제 반복 길이를 분석했다는 뜻은 아닙니다. 수동 구절 이동·기록은 계속 사용할 수 있습니다.
일반 구절의 길이 추정은 `추정 싱크 · 가사 길이 기준`으로 구분해서 표시합니다.
자동 수집은 곡 전환·일시정지·탐색 때에도 확보한 구간을 정밀 분석합니다. 전환 경계의 마지막 1초를 제외하고
10초 이상 남았을 때만 분석하며, 짧게 넘긴 곡은 제외합니다. 중간부터 재생한 구간도 실제로 들린 가사를 별도로 확인해 저장합니다.
저장한 시각과 분석한 시간 구간은 다음 실행에도 유지하며, 다음 재생에서는 미분석 구간을 이어서 처리합니다.
접합부 확인을 위한 최대 2초를 제외하면 저장한 앞부분을 다시 분석하지 않습니다. 기존 확정 시각과 수동 보정은 유지합니다.
가사 앱을 닫으면 창을 숨기고 확보한 자동 수집 구간의 분석·저장을 마친 뒤 종료합니다. 강제 종료나 전원 차단까지 보장하는 기능은 아닙니다.
실패가 반복되어도 재생 정보 확인 때마다 모델을 다시 실행하지 않습니다.
실시간 음원 한 구간의 정렬 오류는 다음 최신 구간에서 다시 확인합니다. 3회 연속 오류면
실시간 추적을 중단하고 이유를 표시하며 전체 수집·종료 후 분석은 계속합니다.
최소화 중에도 접근성 강조를 읽습니다. 같은 강조가 재생 시간 8초 동안 그대로면
마지막 위치부터 추정 진행하고, 강조가 바뀌면 직접 추적을 재개합니다. 긴 구절·간주와
화면 갱신 중단을 완전히 구별하는 방식은 아니므로 정확한 저장 싱크가 있으면 우선합니다.

## 실행

Windows 10/11과 Python 3.10 이상이 필요합니다. 최초 설치:

```powershell
.\setup.ps1
```

그다음 `run.bat`를 실행하고 **더 보기 → 개발자 모드 → 가사 연결**에서 Spotify를 연결합니다.
Spotify 데스크톱에서 곡을 재생하면 저장된 자료와 선택한 제공자를 확인합니다.
웹 플레이어와 휴대폰 단독 재생은 이 버전의 감지 대상이 아닙니다.
같은 데이터 폴더의 앱은 한 번만 실행됩니다. 이미 실행 중이면 알림 영역 아이콘을 왼쪽 클릭해 가사창을 복원하세요.
배포별 변경과 검증 범위는 [릴리스 노트](RELEASE_NOTES.md)에 정리합니다.

`python package_release.py`는 `release/`에 배포용 소스 ZIP을 만듭니다. 허용한 코드와
확장 파일과 공개용으로 정리한 가사·번역·시간표를 포함합니다. 개인 설정·음원·모델·
가상환경·브라우저 프로필·진단 파일은 제외합니다.
소스 ZIP은 Python과 `setup.ps1` 설치가 필요합니다. Windows x64 ZIP에는 EXE와 Electron 런타임이 들어 있으며,
실행할 PC에 Python이나 Node.js를 설치할 필요가 없습니다. [배포용 ZIP 빌드 방법](DISTRIBUTION.md#exe-빌드)
기본 설치에는 Torch와 음원 분석 모델을 넣지 않습니다. 정확한 기존 시간표로 표시하거나
Spotify 강조를 추적할 때에는 별도 음성 모델을 설치할 필요가 없습니다.

가사만 캐시된 곡도 다른 저장 자료의 기존 싱크를 함께 확인합니다. 같은 녹음의
다른 수록본은 기존 시각을 재사용하고, 가창 버전이 다른 경우에는 같은 작품·
가사 전체·곡 길이가 대응하며 기존 시각끼리 충돌하지 않을 때 **기존 곡 참고 싱크**로
빈 시각을 채웁니다. 직접 맞춘 시각과 현재 녹음의 싱크는 우선 유지하고,
참고 시각은 확정 싱크로 저장하지 않으며 현재 버전의 조회·분석을 계속합니다.

## 아래에 띄우고 다른 작업하기

가사창은 기존 어두운 배경과 밝은 가사를 기본으로 항상 위에 표시할 수 있습니다. 가사 표시 설정·음악 사전·개발자 모드는 흰색·분홍색·밝은 회색의 Electron 작업 창에서 엽니다. 제목 표시줄이나 가사 영역을 드래그해 이동하고 가장자리로 크기를 바꿀 수 있습니다.

**헤더 숨기기**는 위쪽 조작줄을 접으며 우클릭 메뉴에서 복원할 수 있습니다. **배경 투명 / 복원**은 배경만 전환합니다. **클릭 통과**를 켜면 뒤의 프로그램을 조작할 수 있으며 알림 영역 아이콘의 오른쪽 클릭 메뉴 또는 설정한 해제 단축키로 되돌립니다.

작은 창에서는 설정한 순서에 따라 제목·가창자·가사 항목을 숨기거나 축소합니다. 이전·다음 구절은 각각 켤 수 있으며 공간이 부족하면 현재 구절을 우선합니다. 창 크기와 적용한 표시는 다음 실행에도 유지됩니다.

## 글자와 배경 설정

상단 **가사 표시 설정** 또는 우클릭 → **가사 표시 설정…**에서 제목, 곡 가창자, 구절 가창자, 원문, 읽는 법, 한국어 번역, 왼쪽 이전 구절과 오른쪽 다음 구절의 표시 여부·글꼴·크기·굵기·색상을 각각 바꿉니다. **배경 · 불투명도**에서는 글자와 배경 불투명도, 배경색과 배경 표시를 조절합니다. **창 축소**에서는 항목의 숨김 순서 또는 전체 축소를 선택합니다.

별도 **가사 미리보기** 창은 설정을 바꾸면 즉시 갱신됩니다. 미리보기를 닫았다면 **미리보기 표시**로 다시 엽니다. 실제 가사창은 **적용**을 누를 때만 바뀌며 **취소** 또는 창 닫기는 편집 중인 표시값을 버립니다. **기본값 복원**도 적용을 눌러야 실제 창에 반영됩니다.

프리셋은 이름을 지정해 여러 개 저장할 수 있습니다. **저장**에서 새 프리셋과 선택한 프리셋 덮어쓰기 중 선택하며, 같은 이름의 새 프리셋은 만들 수 없습니다. 선택한 프리셋을 **불러오기**하면 미리보기와 설정 초안이 바뀌고, 실제 창에는 **적용**할 때 반영됩니다. 저장을 취소하면 프리셋을 바꾸지 않습니다.

우클릭 → **단축키 설정…**에서 이전·다음 구절, 클릭 통과, 헤더, 배경 투명의 키를 지정할 수 있습니다. 기본값은 각각 Ctrl+Alt+↑, Ctrl+Alt+↓, Ctrl+Alt+L, Ctrl+Alt+H, Ctrl+Alt+T입니다. 가사 오버레이 또는 개발자 창에 포커스가 있을 때 동작하며, 사전과 보조 설정창의 일반 키 입력은 유지합니다.

## 나무위키 한국어 번역과 자동 독음

**확장 2.6.1 — 기존 가사창 연결:** [확장 안내](extension/README.md)를 따라 `extension`
폴더를 등록하거나 기존 확장을 새로고침합니다. 앱을 재시작하고 확장의
**Spotify 자동 연동 켜기**를 한 번 누르면 현재 곡의 원본 문서를 비활성 탭으로 열고,
가사 표의 번역·독음을 기존 바탕화면 가사창에 표시합니다. Chrome과 앱은 실행되어 있어야 합니다.

`(… Recording)`·`(… Ver.)` 등 버전 문서에 가사 표가 없으면 일반 제목의 문서를 이어서 확인합니다.
Spotify 가사 또는 아티스트가 맞으면 원곡 가사를 연결하되, 싱크는 재생 중인 녹음의
제목·아티스트·앨범 기준으로 별도 저장합니다. 두 정보가 없어도 후보 탐색 후 제목과 가사 표가
확인된 문서가 하나만 남으면 자동 연결합니다. 가사 후보가 여러 개이면 선택으로 남깁니다.

확장은 원본 페이지 DOM을 유지하고 선택된 표를 메모리에서 localhost의 앱으로 전달합니다.
확장 자체는 본문을 파일·DB·Chrome 저장소에 저장하거나 외부 서버로 보내지 않습니다.
앱은 검증된 가사를 `data/lyrics_cache/`에 보관해 다음 청취 때 원본 연결을 기다리지 않고 먼저 표시합니다.
정확히 같은 녹음의 캐시가 없으면 재생 캐시와 저장한 플레이리스트 가사에서 같은 곡의 다른 발매본도 찾습니다.
GAME/TV/SHORT 및 가창자 Ver. 표기와 앨범 차이를 구분하며, 가사는 길이 차이 30초 이내에서 재사용합니다.
가창자가 달라도 로컬 곡 사전의 두 가창 기록·공통 시리즈 또는 검토된 공식 작품 연결로 같은 작품을 확인하면
가사·독음·번역을 먼저 불러옵니다. 줄바꿈 차이는 허용하지만 원문이 충돌하는 후보는 임의로 고르지 않습니다.
같은 가창의 시간표는 길이 차이 2초 이내이고 가사 행과 저장 후보들이 일치할 때만 `저장 캐시`로 표시합니다.
다른 가창의 시간표는 같은 편집·길이 차이 2초 이내여도 실시간 검색 시작 행을 찾는 참고값으로만 사용하며,
현재 음원에서 확인하기 전에는 확정 싱크로 표시하지 않습니다. 30초 차이가 나는 경우는 시간표를 가져오지 않고 현재 음원에 다시 정렬합니다.
다른 편곡·동명곡, 서로 충돌하는 시각, 길이가 크게 다른 게임 편집본에는 시간표를 복사하거나 비율로 늘이지 않습니다.
최초 녹음의 길이를 함께 보관해 여러 발매본을 거치면서 허용 오차가 누적되지 않으며, 현재 곡의 수동 보정이 우선합니다.
곡이 바뀌거나 앱을 닫으면 현재 표시용 메모리는 해제하며, 저장한 캐시는 유지합니다.

등록된 곡은 일본어 구절을 대조해 번역·독음을 보충하고 기존 시간표를 사용합니다.
미등록 곡도 받은 가사로 표시하고, 제공자 싱크가 없으면 가사 길이로 진행합니다. 직접 기록한 시간표와
보정값은 `data/live_timings`에 숫자·가사 순서의 해시만 저장하고 다음 연결 때 복원합니다.
원문이 바뀌면 시간표를 재사용하지 않습니다. 가사 캐시와 별개로 음원 분석에는 본문을 메모리 파이프로 전달하며 분석용 가사 임시 파일을 만들지 않습니다.
Spotify 원문이 있으면 두 구절 이상 대조하고, 없으면 제목·아티스트로 문서를 확인합니다.
제목이 맞는 가사 문서에 다른 후보가 없으면 자동 연결하고, 구분되지 않는 동명 후보는 확장 팝업에서 선택합니다.
선택하거나 자동 연결 후 표시가 성공한 문서 URL은 다음 연결에도 사용합니다. Spotify를 축소해도 곡 감지와 원본 문서 연결은 동작합니다.
축소 중에는 강조 색상 대신 재생 시간과 저장된 싱크를 사용하고, 싱크가 없으면 추정 진행합니다.
Spotify 화면에서 새 원문을 읽으려면 가사 화면이 열려 있어야 합니다. OCR 보완은 전면 창에서만 동작합니다. 화면 캡처와
화면에서만 읽은 본문은 메모리에만 두며 다른 앱 화면은 읽지 않습니다. 같은 제목의 후보 링크가
원본 페이지에 없거나 가사 표 형식이 다르면 연결되지 않을 수 있습니다.
문서 URL은 data/wiki_documents.json에 곡 구분값과 함께 보관하며, 자동 학습 주소는 직접 지정한 주소와 구분합니다.

원본 탭을 닫아도 자동 연동을 유지하며 다음 곡에서 새 탭으로 연결합니다.
페이지 로딩·로컬 통신 실패는 5/15/30초 후 최대 3회 재시도합니다. 사이트 접근 제한은 자동 재시도하지 않습니다.
수동 읽기 모드 버튼은 기존처럼 원본 DOM의 표시만 바꾸며 앱에 전송하지 않습니다.

이전에 TXT나 붙여넣기로 가져와 저장한 가사는 계속 사용할 수 있습니다.
이전 버전에서 받은 파일의 수신·보충 캐시도 호환성을 위해 유지하지만, 새 확장은 파일을 만들지 않습니다.

기존 TXT와 저장된 가사·문서 연결은 계속 읽습니다. 자동 조회는 원문과 문서의 대응을 확인하며, 접근이 제한된 사이트는 반복 요청하지 않습니다.

후리가나는 [fugashi와 UniDic-lite](https://github.com/polm/fugashi)의 문맥을 고려한
일본어 분석과 pykakasi 보완으로 생성합니다. 별도 API나 음성 모델은 쓰지 않습니다.
가수 고유의 독음·인명·노랫말의 특수 독음은 틀릴 수 있습니다.

## 싱크 맞추기

가사는 저장된 시간표와 선택한 제공자의 싱크를 우선 사용하고, 시각이 없는 구절은 설정된 추정에 따라 진행합니다. 기존 수동 기록과 곡별 보정은 계속 읽으며 자동 자료가 이를 덮어쓰지 않습니다.

직접 고치려면 **더 보기 → 개발자 모드**를 열고 현재 곡의 구절을 선택하세요. **← / →**로 구절을 선택하고 **Enter** 또는 **선택 줄 기록**으로 선택 줄의 시작을 기록합니다. **↓**는 다음 줄 시작, **↑**는 앞 줄의 끝과 현재 줄의 시작을 기록합니다. **선택 줄 싱크 지우기** 또는 Delete는 선택 줄의 시각을 지웁니다. 기존 기록과 순서가 충돌하면 저장하지 않고 오류를 표시합니다.

개발자 모드의 **싱크 −0.25초 / 싱크 +0.25초**로 곡 전체 표시를 조절하고, **표시 선행 (ms)** 값을 입력한 뒤 **적용**하면 화면 표시만 앞당깁니다. 직접 수정한 시간표와 제공자 자료는 보존됩니다.

## Spotify 재생음으로 싱크 분석 (선택 기능)

배포 기본 기능은 재생 정보·저장된 시간표·Spotify 강조 추적이며, 음원 분석은 기본으로
꺼져 있습니다. 저장한 싱크가 있는 가져온 곡은 중복 화면 읽기를 쉬고, 이미 가사가
연결된 곡은 원문을 다시 찾는 OCR을 생략합니다. 다른 곡의 실제 강조 추적은 유지합니다.

이 PC에는 분석 모듈과 small 모델을 설치했습니다. 다른 PC에서는 **개발자 모드 → 음원 분석 → AI 선택 설치…**에서 선택해 받거나
`setup-audio.ps1`을 한 번 실행하세요. 모델 자체는 약 486MB이며, 가사를 음원에 직접
정렬하는 실행 라이브러리·사전·Python·내부 브라우저 모듈을 정리한 시험본은 압축 전 약 1.76GB,
ZIP 약 846MB였습니다. 구성·검증 범위는 [배포 용량 실측](BUNDLE_SIZE.md)을 참고하세요.
새 선택 설치에도 같은 빌드 파일 제외 처리를 연결했습니다. 기존 사용자 설치는 그대로 두었습니다.
기본 CPU 모드에는 GPU/CUDA 설치나 API 키가 필요하지 않습니다. 처음 모델을 받을 때만 인터넷이 필요하고,
이후 음원·가사는 로컬에서 처리합니다.

1. Spotify에서 분석할 곡을 선택하고 가사 앱의 **더 보기 → 개발자 모드 → 음원 분석…**을 엽니다.
2. **분석 시작**을 누릅니다. 보관된 분석용 음원이 있으면 바로 재분석합니다. 처음 분석할 때는 3분 안에 Spotify에서 해당 곡을 **처음부터 재생**합니다.
3. 재생 중 짧은 음원으로 구절을 추적하고, 한 곡을 끝까지 들으면 전체 음원을 분석합니다. 일시정지·탐색 시 취소됩니다.
   곡이 바뀌면 받은 구간만 분석합니다(10초 이상 수집했을 때). 마지막 1초를 잘라
   곡 전환 경계의 소리가 섞이는 것을 줄입니다. 크로스페이드는 꺼 두는 편이 좋습니다.
4. 분석 후보를 확인하고 **빈 구절에 적용**을 누릅니다. 기존 기록·보정값은 보존합니다.
   기존 시간과 충돌하는 후보는 건너뜁니다. 완전히 기록된 곡에는 새로 적용하지 않습니다.
5. 다음 재생부터 저장한 시간표를 사용합니다. 어긋난 부분은 개발자 모드에서 보정하세요.

실시간 가사의 자동 분석 후보도 같은 창에서 **실시간 가사 분석 후보 · 보기 전용** 탭으로 확인할 수 있습니다.
이 후보 탭은 시간표를 변경하지 않으며, 곡이 바뀌어도 적용 버튼이 활성화되지 않습니다.
분석 결과의 저장이 실패하면 오류를 표시하고 기존 후보·시간표를 보존합니다.
후보만 저장된 경우에는 시간표 적용 완료와 구분해 표시합니다.

조회·분석을 시작한 뒤 같은 제목·가수·앨범의 재생 길이가 2초 넘게 바뀌면 이전 응답을 제외합니다.
길이가 다른 것으로 확인된 분석 후보는 적용과 자동값 복원 전에 중단하며, 기존 기록을 유지합니다.
길이 정보가 없는 옛 시간표를 녹음별로 자동 분리하거나 어느 버전의 기록인지 추정하지는 않습니다.

Windows의 프로세스별 캡처로 **Spotify 데스크톱 앱과 그 하위 프로세스의 소리만** 받습니다.
브라우저 영상·통화·알림·마이크는 포함하지 않으며 출력 장치가 달라도 Spotify를 대상으로 합니다.
이 분석 기능에는 Windows 11 또는 빌드 20348 이상이 필요합니다. 연결할 수 없으면 이유를 표시하고
중단하며 PC 전체 소리로 전환하지 않습니다. Spotify 자체의 크로스페이드·광고는 섞일 수 있습니다.
분석창의 **분석 취소**, 분석창 닫기 또는 앱 종료로 수동 수집을 중단합니다.
가사 위에도 대기/수집/분석 상태가 표시됩니다. 자동 분석 옵션이 꺼져 있으면
직접 분석 대기를 시작할 때만 수집합니다.

한 곡 최대 15분입니다. 기본 CPU 분석 프로세스는 낮은 우선순위, CPU 1스레드와
INT8 small 모델을 사용합니다. Windows Job Object로 분석 프로세스의 CPU 사용을
전체 CPU의 최대 3%, 프로세스 메모리 할당을 1GiB로 제한합니다. 제한 설정이 실패하면
분석을 시작하지 않습니다. 실시간 추적과 전체 분석은 단계별로 한 곡씩이며, 제한 때문에 완료가 늦어질 수 있습니다.
지원되는 Windows에서는 절전 우선 처리(EcoQoS)도 요청합니다. CPU 사용률 제한과 별개이며,
기기 냉각 상태나 다른 프로그램의 부하까지 제어하는 기능은 아닙니다.
분석할 때만 모델을 올리고 종료하면 메모리를 반환합니다. 이 제한은 가사 표시나 녹음
프로세스에는 적용하지 않습니다. 실제 분석 정확도는 기존 검증 수준이며 자원 제한만으로
정확도가 높아지는 것은 아닙니다. 배포에 큰 비교용 모델은 포함하지 않습니다.
수집 중인 음원과 실시간 분석 구간은 앱 전용 `.sloa` 데이터로 처리하고 작업 종료 시 임시 폴더에서 정리합니다.
곡 전체를 수집했고 싱크가 미확정이거나 재분석이 필요한 경우에만 16kHz 모노 분석 데이터와 재생 시각 정보를
`data/audio_captures/`에 보관합니다. 싱크를 완성하면 전용 데이터를 정리합니다. 이전에 저장한 WAV는 재분석에서 계속 읽을 수 있습니다.
Windows 파일 잠금 등으로 임시 파일을 지우지 못하면 작업 대기열은 정상 종료하고 정리 실패를 따로 알립니다.
분석 창의 진행 상세에서 남은 임시 폴더 위치를 확인할 수 있으며, 분석 결과와 기존 시간표의 저장 상태는 유지합니다.

기본 분석은 [stable-ts](https://github.com/jianfch/stable-ts)의 가사 직접 정렬입니다.
이미 있는 일본어 가사를 small 모델의 음원 위치와 대응시킵니다. 새 가사를 받아쓰는
방식보다 이 기준곡에서 더 많은 구절을 찾았습니다. 반주·합창·늘여 부르는 발음·반복
후렴 때문에 오류나 누락이 생길 수 있습니다. 시간이 겹쳐 압축된 구절, 신뢰도가 낮은
구절, 시작을 확인할 수 없는 구절은 빈 시간으로 남기며 기존 길이 추정/직접 기록을
사용합니다. 앞뒤 시작을 확인한 누락 구절은 최대 45초의 짧은 구간으로 다시 분석하며,
두 경계의 시각이 각각 1초 이내로 유지되고, 새 시작 시각이 전체 곡 분석의 해당 구절
시각과 1.5초 이내일 때만 후보를 추가합니다. 서로 크게 다른 결과는 확정하지 않습니다. 화면의
**음원 분석 후보 적용됨**도 정확도를 보장한다는 뜻은 아닙니다.

### 재생해 두고 자동 분석하기

**개발자 모드**에서 **자동 분석 · Spotify 소리만**을 켭니다.
켜짐/꺼짐은 다음 실행에도 유지됩니다. 끄면 진행 중인 자동 수집·분석을 취소하며 저장된 싱크는 계속 씁니다.
가사를 찾는 동안에도 Spotify 소리부터 임시 수집합니다. 원문이 도착하면 같은 수집 작업에 연결하므로,
곡 시작부터 받은 앞부분도 전체 분석에 포함됩니다. 이때 상태줄에 **가사 검색 중 · 음원 먼저 수집**을 표시합니다.
확정 싱크를 찾거나 가사 없는 상태에서 곡을 넘김·일시정지·탐색하면 불필요한 수집은 취소하고 임시 음원을 정리합니다.
가사가 끝내 도착하지 않으면 모델을 실행하지 않고 음원을 삭제합니다. **첫 청취는 임시 추적 → 곡 종료 후
전체 분석·저장 → 다음 청취는 저장 싱크** 순서입니다. 분석 완료 전 재생에는 임시 결과를 사용합니다.
새 분석은 이전 자동
분석 시각을 만들며 직접 기록·편집한 시각은 보존합니다. 이미 자동 시각이나 같은 원문의
분석 초안이 있는 곡은 빈칸·부분 분석·수동 수정·예전 분석 버전 여부와 관계없이 재수집하지 않습니다.
다시 분석하려면 음원 분석 창에서 **분석 시작**을 누르세요. 해당 녹음의 보관본이 있으면 재생 없이 다시 분석합니다. 과거 기록 중 자동/수동
구분이 불명확한 값도 보존합니다. 완성된 수동 시간표는 분석하지 않습니다. 저장 전 원본 시간표를
`data/audio_backups/`에 한 번 백업합니다. 실패는 상태에 표시하고 다음 곡을 기다립니다.

앞 곡을 분석하는 동안 다음 곡의 소리를 받을 수 있습니다. 전체 분석과 실시간 추적은
각각 한 번에 하나만 실행하고 수집·대기·분석 합계 최대 3곡으로 제한합니다. 대기가 가득 찬 곡은
건너뜁니다. 곡을 넘길 때 아직 수집을 시작하지 못한 자동 재생 대기는 즉시 취소하고 목록에서 정리합니다.
이미 수집을 마친 곡의 분석과 직접 시작한 재생 대기는 유지합니다. 실패한 수집은 다음에 그 곡을 처음부터 재생하면 한 번 재시도합니다.
앱 실행 중 곡별 최대 2회이며, 대기열이 찬 곡은 분석 완료로 처리하지 않습니다.
중간 재생에서 시작한 수집은 임시 추적에 사용하고, 이미 앞부분부터 수집한 작업에는 늦게 찾은 가사를 이어 붙입니다.
일시정지·탐색은 해당 수집을 취소합니다.
일치가 전체의 60% 미만이거나 3구절 미만이면 후보만 보관하고 자동 저장하지 않습니다.

PC와 앱을 켜고 Spotify를 계속 재생하면 사용자 조작 없이 처리됩니다. 절전·종료하면
계속 수집할 수 없습니다. 첫 청취 중에는 아래의 부분 음원 추적을 사용하고, **한 곡을
받고 분석한 뒤 다음 재생부터** 저장된 음원 분석 시각을 사용합니다.
실제 소리를 확인하는 시간이 필요하므로 첫 청취의 표시에는 지연과 누락이 생길 수 있습니다.

## 파일과 검증

`sync_review.py`는 28곡 같은 기존 라이브러리의 저장 상태를 점검하거나 로컬 음원을
분석하고 수동 기준과 비교합니다. 음원 파일은 읽기만 하고 외부로 전송하지 않습니다.
결과는 숫자 시각·오차·곡 정보만 포함하며 기존 시간표에 자동 덮어쓰지 않습니다.

```powershell
.\.venv\Scripts\python.exe sync_review.py
.\.venv\Scripts\python.exe sync_review.py --audio '노래.flac' --song '곡 제목' --output '검토.json'
```

`data/sync_reviews/`: 라이브러리 점검과 음원별 비교 결과.
`data/native_timings/`: 연속 관측한 Spotify 구절 전환 시각과 곡 내용 해시.

`data/library.json`: 가져온 가사 사본. 원본 TXT는 변경하지 않습니다.
`data/lyrics_cache/`: 검증된 문서·API 가사와 제공자 싱크. 최대 200개·32MiB이며 수동 시간표와 별도입니다.
`data/timings/`: 곡별 시간표·보정값. `data/settings.json`: 표시 설정·곡 연결.
`data/lyric_annotations/`: 기존 일본어 구절에 대응하는 보충 번역·독음. 원본 가사·시간표와 별도 저장.
`data/audio_drafts/`: 곡별 음원 분석 후보(수동 분석은 미리보기 후 적용, 자동 모드는 빈 시간에 적용).
`data/audio_backups/`: 자동 분석이 최초로 저장하기 전 시간표 백업.
`models/whisper-small/`: 최초 한 번 설치하는 로컬 모델.
가사를 재가져올 때 줄 내용/순서가 변경되면 이전 시간표를 자동 재사용하지 않습니다.
개인 가사와 설정이 담긴 `data/`는 버전 관리·배포 대상에 포함하지 마세요.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m py_compile app.py lyrics.py storage.py sync.py media.py windows.py subtitle.py
.\.venv\Scripts\python.exe -m py_compile audio_job.py audio_worker.py audio_sync.py
.\.venv\Scripts\python.exe -m py_compile auto_audio.py appearance.py web_lyrics.py web_dialog.py
.\.venv\Scripts\python.exe -m py_compile audio_alignment.py
```

구조: `lyrics.py`는 파싱과 곡 매칭, `media.py`는 Spotify 읽기, `sync.py`는 시간표,
`storage.py`는 로컬 저장, `windows.py`는 단축키와 창 속성, `app.py`는 화면을 담당합니다.
`lyric_match.py`는 구절 순서를 정렬하고 `lyric_merge.py`는 수집 경로에 공통인 원문·독음·번역·시각 병합을 담당합니다.
`subtitle.py`는 배경을 투명하게 해도 읽을 수 있는 외곽선 글자와 줄바꿈을 담당합니다.
`audio_job.py`는 별도 프로세스·취소·임시 파일의 수명을 관리하고, `audio_worker.py`는
수집 흐름과 선택 설치 모델 실행, `process_audio.py`는 Windows의 Spotify 전용 소리 수집,
`audio_sync.py`는 구절 대조와 기존 기록 보존을
담당합니다. `tests/test_audio.py`는 분석 후보·재생 중단·UI 회귀를,
`tests/test_audio_process.py`는 프로세스 종료·취소와 임시 음원 정리를 검증합니다.
`tests/test_process_audio.py`는 전용 수집의 시간 기준·버퍼 누락·무음·일시정지 처리를 검증합니다.
`auto_audio.py`는 자동 분석 대기·보존 저장, `web_lyrics.py`는 웹 표 파싱·독음,
`web_dialog.py`는 가사 미리보기, `appearance.py`는 독립 배경과 표시 설정을 담당합니다.
`audio_progress.py`는 자동·직접 분석의 단계별 진행률과 남은 시간 추정을 메모리에서 계산하며,
`tests/test_audio_progress.py`와 `tests/test_audio_progress_ui.py`에서 상태 전이·창 재열기·작은 창 배치를 검사합니다.
`internal_reader.py`는 내부 브라우저 프로세스와 앱 표시 응답을 연결하고, `browser_worker.py`는
WebView2 실행·제한된 문서 후보 탐색을 담당합니다. `native_page.js`는 확장과 동일한
DOM 파서·문서 대조 함수를 사용합니다. `reader_dialog.py`는 연결 방식·상태·후보 선택 UI입니다.
관련 검사는 `tests/test_internal_reader.py`, `tests/test_reader_dialog.py`에서 실행합니다.
`audio_alignment.py`는 제공 가사의 음원 정렬과 구절별 후보 검사를 담당합니다.
`extension/`은 사용자 클릭으로 원본 DOM의 표시를 바꾸는 읽기 모드입니다.
`extension_inbox.py`는 이전 버전의 로컬 전송 파일 호환용입니다.
`node --test tests/extension.test.js`로 읽기 모드의 Chrome API 흐름을 검사합니다.
`lyric_annotations.py`는 일본어 구절 대조와 보충 내용 저장·표시를 담당하며
`tests/test_lyric_annotations.py`와 가져오기 UI 테스트에서 저장 후 재사용과 기존 싱크 보존을 검사합니다.

Windows가 재생 위치를 제공하지 않거나 다른 버전의 음원이면 자동 싱크가 정확하지
않을 수 있습니다. 공개 싱크의 존재 여부도 곡마다 다릅니다. 직접 기록과 보정은
네트워크 없이 사용할 수 있습니다.

## 첫 재생 음원 추적과 종료 후 전체 분석

**음원 분석 창 → 진행 중·대기**에서 곡별 수집·분석·순서 대기 상태를 확인합니다.
창을 다시 열어도 실행 중인 자동 작업의 상태를 바로 표시하며, 표시 정보는 약 0.5초마다 갱신합니다.
진행률은 실제 수집량·분석 콜백으로만 바뀝니다. 곡을 바꾸면 이전 곡의 전체 분석과 현재 곡의
수집을 각각 보여 줍니다. 목록에서 곡을 선택하면 경과 시간·마지막 진행 수치 갱신·오류 이유를 볼 수 있습니다.
자동 분석 오류는 재시작 후에도 확인할 수 있도록 데이터 폴더의 `audio_failures.json`에 최근 20건의
곡 제목·실패 단계·오류 종류·코드 위치만 남깁니다. 음원·가사·절대 경로·예외 원문은 기록하지 않습니다.
분석이 정상적으로 끝나도 확실한 시각을 찾지 못한 경우는 `분석 완료 · 일치 구절 부족`으로 표시합니다.
기존 시간표를 보존하고 다음 재생에서 최대 한 번 다시 시도합니다.
남은 시간은 **현재 단계**의 추정치입니다. 수집은 남은 음원 길이, 분석은 실제 진행 속도로 계산합니다.
모델 준비 중이거나 진행 표본이 부족하면 `계산 중`, 아직 시작하지 않았으면 `순서 대기`로 표시합니다.
분석 수치가 오래 갱신되지 않으면 남은 시간 추정을 보류합니다. 대기 시간을 포함한 전체 완료 시각은 예측하지 않습니다.
`싱크 후보` 탭에서는 기존처럼 후보를 확인하고 빈 구절에 적용합니다.
창을 닫아도 자동 작업은 계속됩니다. 직접 시작한 작업은 기존처럼 창을 닫으면 취소됩니다.
이 표시는 기존 작업의 메모리 정보만 사용하며 모델 호출·CPU 상한·시간표를 변경하지 않습니다.

개발자 모드의 자동 분석을 켜면, 가사가 연결된 곡을 처음부터 재생할 때 두 단계를 실행합니다.
기본 CPU 모드의 첫 재생에서는 최근 최대 3초의 소리와 현재·인접 구절을 기존 small 모델로 대조합니다.
새 구간은 약 1초마다 확인하고, 분석이 늦으면 오래된 구간을 쌓지 않고 최신 구간을 사용합니다.
모델의 음원 특징 입력도 그 짧은 구간만 사용합니다. 가사 일부의 발음이 충분히 대응하면
전체 문장이 끝나기 전에 현재 구절을 표시합니다. 아직 찾은 구절이 없거나 마지막 일치가
6초 이상 오래되면 추정 설정에 따라 임시로 진행하고 ‘음원 구절 확인 중 · 임시 진행’으로
표시합니다. 가사 길이 추정을 음원 인식 결과로 표시하지 않습니다.
실제 소리의 일부와 처리 시간이 필요하므로 지연 없는 동시 표시는 아니며, 노래·반주에 따라
구절을 놓칠 수 있습니다. 화면의 ‘실시간 음원 대조 · 임시 추적’으로 기존 추정 모드와 구분합니다.
처음 구절을 찾지 못하면 첫 여섯 구절 안에서 대조 범위를 바꿔 다시 확인합니다.
한 번에 처리하는 가사는 세 구절로 유지하며, 뒤쪽 구절에서 시작하려면 강한 고유 발음이
서로 다른 구간에서 두 번 확인되어야 합니다. 첫 여섯 구절을 모두 놓치면 추적을 시작하지 못할 수 있습니다.

**음원 속도 예측**은 소리로 확인한 연속 구절의 위치 간격 두 개 이상과 독음 길이로 최근 빠르기를
구합니다. 정확한 시작점을 찾지 못하면 그 구절에서 인식된 부분의 위치를 임시 기준으로 씁니다.
새 분석 결과를 기다리는 동안 재생 시계에 맞춰 다음 한 구절을 미리 표시하며 화면에
`음원 속도 예측 · 다음 구절 임시 표시`라고 구분합니다. 확인되지 않은 두 번째 줄까지
계속 넘어가지는 않습니다. 소리 근거가 오래됐거나 간주·큰 속도 변화가 감지되면 예측을
멈추고, 실제 음원이 이전 구절을 지지하면 되돌려 보정합니다. 수동으로 고친 시각은 예측보다
우선합니다. 이 과정은 모델 호출이나 저장 시각을 추가하지 않는 표시 보완이며 틀릴 수 있습니다.

곡 수집이 끝나면 전체 음원과 전체 원문을 기존 제공 가사 정렬 방식으로 분석합니다.
오디오 수신은 전용 스레드에서 실행하여 임시 파일 쓰기가 늦어져도 패킷을 놓치지 않게 합니다.
최대 5초의 처리 대기 버퍼를 두며, 실제 음원 손실이나 버퍼 초과가 확인되면 잘못된 시각을 저장하지 않습니다.
자동 분석 모드에서는 충분한 후보가 있는 결과만 기존 수동 기록을 보존하며 적용합니다.
완전한 수집을 분석한 시간표는 다음 재생 때 우선 사용하고 반복 분석하지 않습니다.
확인하지 못한 구절은 빈칸으로 남으며, 추정 설정을 켜면 그 빈 구절만 추정합니다.
수동으로 시작한 분석은 기존처럼 후보를 확인한 뒤 적용할 수 있습니다.

기본 CPU 모드의 실시간 분석은 최대 CPU 2%, 전체 분석은 최대 CPU 1%로 제한합니다. 각 단계는 동시에
한 모델만 실행하므로 두 단계가 겹쳐도 분석 CPU 상한은 합계 3%입니다. 각각 1스레드이며
모델은 가사 창과 별도 프로세스에서 실행되고 완료·취소 시 메모리를 반환합니다.
실시간용 새 모델이나 API 키는 필요 없습니다. 기존 small 모델을 재사용합니다.

### GPU 실시간 추적 (2026-10-04)

GPU 사용을 선택한 설치에서는 최근 8초의 재생음에 현재·인접 가사를 약 1초마다 직접 정렬합니다.
짧은 문맥에서 반주를 가사로 오인하지 않도록 처음에는 8초 분량이 모일 때까지 기다립니다.
위치를 얻지 못하거나 여러 구간 동안 진행이 멈추면 일본어를 독립적으로 인식하여 원문과 로컬 발음을 비교합니다.
이 복구용 인식에는 실제 가사 전체를 프롬프트로 넣지 않습니다.
최근 확인 위치 근처의 짧은 구절은 겹치는 두 음원 구간에서 확인하고, 먼 위치는 고유한 인접 두 구절과 시각 순서를 확인합니다.
동일 후렴의 다른 위치로 임의 이동하거나, 불확실한 인식 사이를 붙여 새 문장을 만들지 않습니다.
창 끝의 저신뢰 인식은 별도 구간으로 버리고 직전에 확인한 구절을 유지합니다.
이 임시 결과는 정밀 시간표로 저장하지 않으며 수동·공급자·기존 완성 싱크를 우선합니다.

`data/settings.json`의 `audio_device`는 `auto`(기본, 가능하면 NVIDIA GPU) 또는 `cpu`입니다.
앱을 닫고 변경한 뒤 다시 실행합니다.
명시적으로 AI 설치를 시작하면 NVIDIA 드라이버가 감지된 환경에 cuBLAS 12·cuDNN 9 런타임과 Whisper medium을 설치합니다. 소스 설치에서 `setup-audio.ps1 -Gpu`로 이 구성을 직접 선택할 수 있습니다.
선택 설치는 GPU 런타임을 프로젝트 또는 앱의 전용 Python 환경에 추가합니다.
로컬 `models/whisper-medium`이 있으면 GPU에서 사용하고 없으면 기존 small을 사용합니다.
이 PC의 일본어 노래 표본에서 small·medium·turbo를 비교한 뒤 medium을 선택했습니다.
Kira Kira의 전체 녹음으로 자유 인식과 3초·8초 가사 직접 정렬을 다시 비교해 8초 직접 정렬을 기본으로 바꿨습니다.
큰 모델이 항상 우수하다는 뜻은 아니며, turbo의 상투적 환각은 가사 대조에서 제외했습니다.
GPU 초기 계산까지 확인하고 사용할 수 없으면 상태를 알린 뒤 CPU 소형 모델로 전환합니다.
GPU 모드 워커는 각각 CPU 상한 20%·호스트 메모리 할당 상한 4GiB·CPU 2스레드이며,
이는 VRAM 상한이 아닙니다. 곡 종료 후 정렬은 로컬 `models/whisper-turbo`의 필수 파일이
완비되어 있으면 GPU에서 turbo를 사용하며, 없으면 small을 사용합니다. CPU 복구도 small입니다.
실시간 medium과 종료 후 정렬은 별도 프로세스에서 동작하며, 종료 후 정렬끼리는 순서대로 처리합니다.
GPU 로딩이나 전체 정렬이 실패하면 상태를 알리고 CPU로 한 번 다시 분석합니다.
처리 완료가 늦어진 구간은 버리고 최신 음원을 받으므로 대기열에 지연이 누적되지 않습니다.
두 GPU 작업이 겹치면 잠시 지연될 수 있으며 상태줄에 표시합니다. 버린 구간은 직접 정렬과 인식기의 상태도 함께 복원합니다.

부분 녹음은 일본어 원문과 독음으로 실제 들린 구절을 먼저 찾습니다. 전체 가사와 짧은 음원을
한꺼번에 대조하지 않고, 확인된 가사 범위와 음원 범위를 함께 잘라 정렬합니다. 멀리 떨어진 구절은
별도 구간으로 처리하며, 반복 후렴은 다른 고유 구절의 순서와 시각으로 구별될 때만 사용합니다.
행 중간·끝의 괄호 속 추임새는 본 가사와 별도로 대조합니다. 행 앞의 콜은 시작 시각을 바꿀 수 있어
임의로 지우지 않습니다. 표시·저장되는 가사 원문은 바꾸지 않습니다.
전체 정렬이 0구절로 끝나면 같은 음원에서 확인된 일부 구간을 다시 대조해 회복을 시도합니다.

2026-10-04 로컬 녹음 비교에서 YESTERDAYS의 60.2초 표본은 기존 2구절에서 5구절,
修楽旅行의 162.92초 표본은 가사 전체 3중 중복을 정리하고 대조 방식·모델을 함께 바꾼 뒤
0구절에서 9구절의 시각을 반환했습니다. 이는 내부 일치 검증을 통과한 후보 수이며,
사람이 정답 시각을 매긴 정확도 평가나 전곡 완성률이 아닙니다. 모델만 바꾼 효과로 해석하지 않습니다.

오랫동안 위치를 놓쳤을 때는 원래 검색 범위 밖에서도 고유한 인접 두 구절과 실제 음원 시각 순서를
함께 확인해 복귀합니다. 반복 후렴은 그 직전 고유 구절이 확인된 경우에만 이어서 추적합니다.
재생 시간 비율만으로 멀리 있는 가사행을 확정하지 않습니다.
작은 가사창에도 분석 상태줄을 표시합니다. 모델 준비·구절 미확인·확인된 행·재탐색·수집률을 구분하며,
다음 곡으로 넘어가도 이전 곡의 전체 분석과 최근 종료 결과 3건을 확인할 수 있습니다.

다른 곡 때문에 기다리는 작업은 별도로 `분석 순서 대기`로 표시합니다.
